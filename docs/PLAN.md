# Book_Tran 기획서 (MVP)

## 목표
원본 EPUB/PDF의 형식을 유지한 채 번역해, 진짜 문서처럼 읽을 수 있게 한다.
사용 범위: 개인 사용(본인 전용). 과금/구독은 고려하지 않는다.

## 확정 결정
| 항목 | 결정 |
|---|---|
| 1차 포맷 | EPUB (reflowable) |
| PDF | MVP 이후(베타). 텍스트 PDF부터 오버레이 방식 |
| 번역 엔진 기본값 | Gemini (Google AI Studio API) |
| 번역 엔진 구조 | 어댑터 방식. Claude, OpenAI, DeepL 교체 가능 |
| 처리 위치 | 백엔드(Python) 처리, Flutter는 클라이언트 |
| 앱 플랫폼 | Windows 우선 (Android는 이후) |
| MVP 뷰어 | 원본 / 번역 / 나란히 보기 / 토글 |
| 번역 상태 | 번역 결과와 문단 대응표를 저장하고 재사용 |
| MVP 이후 | 문장 단위 대조, 번역 수정, 용어집 UI |

## 핵심 원칙
- 형식 보존은 백엔드가 책임진다. 앱은 번역된 파일을 그대로 연다.
- EPUB의 이미지, CSS, 폰트, 목차 구조는 바이트 단위로 유지하고 텍스트 노드만 바꾼다.
- 번역 실패 블록은 원문을 그대로 둔다. 파일이 깨지는 것보다 원문 노출이 낫다.
- 번역문과 원문의 문단 대응표를 저장해 나란히 보기와 위치 동기화에 쓴다.

## 백엔드 구성 (backend/)
- `epub_translate.py`: EPUB 파싱, 블록 추출, 인라인 마커 치환, 재조립
- `providers/`: 번역 엔진 어댑터 (`gemini.py`, 테스트용 `fake.py`)
- `cache.py`: 문장 단위 번역 캐시 (SQLite)
- `api.py`: 업로드, 번역 실행, 결과 다운로드, 대응표 조회 (FastAPI)

## 이번 슬라이스 완료 기준
1. 작은 EPUB을 업로드하면 번역 EPUB이 생성된다.
2. 결과 EPUB은 zip 구조(mimetype 첫 항목, 무압축)를 지키고, 이미지와 CSS는 원본과 동일하다.
3. 인라인 태그(`<em>`, `<a>` 등)는 번역 후에도 보존된다.
4. 문단 대응표(원문/번역 쌍)를 JSON으로 제공한다.
5. 번역 캐시로 같은 문장은 재요청하지 않는다.

## 열린 항목
- Flutter SDK 설치 (로컬 환경에 없음)
- Gemini API 키 (환경변수 `GEMINI_API_KEY`로 주입, 저장소에 넣지 않음)
- Gemini 모델 ID는 설정값으로 분리 (기본값은 설정 파일에서 변경)
